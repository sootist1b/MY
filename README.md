# demo — Executive Operations Dashboard

경영진용 MYD 운영 대시보드. `index.html`을 브라우저에서 열면 실행됩니다. 빌드, 외부 CDN, API 키가 필요하지 않습니다. `index.html` 한 파일에 최신 CSS·JavaScript를 포함했으므로 이 HTML만 내려받아 열어도 같은 화면이 동작합니다.

로컬 HTTP로 실행하려면:

```sh
cd /workspace/MY
python -m http.server 8000 --bind 0.0.0.0
```

수정 소스는 `dashboard.js`, `dashboard.css`, `chart-samples.js`입니다. 변경 후 `python scripts/embed-dashboard.py`로 단일 HTML에 반영하세요. GitHub 원격에 변경을 반영하기 전에는 GitHub의 HTML이 로컬 작업본과 다릅니다.

## 화면과 분석 흐름

- **통합현황**: 기존 샘플 12행 × 36열 전체 표시.
- **입고 실적·진척**: 12행 × 22열, 월별 입고와 계획·실적 비교.
- **공출 실적·재공**: 21행 × 23열, 모든 기준일의 원본 행 표시.
- **공급·CHIP 진척**: 12행 × 30열, 입고 및 CHIP 확보 현황.
- **자재 확보·리스크**: 16행 × 18열, 목표와 M0 보유량, GEO RISK.
- **차트라이브러리**: 70종을 각각 독립된 샘플 SVG로 표시합니다. 불릿·게이지·워터폴·비교 막대·덤벨·슬로프·추이선·면적·예측 밴드·도넛·트리맵·퍼널·생키·리스크 매트릭스·산점도·버블·상자수염·레이더·간트·코호트·파레토·캘린더·민감도·선버스트·바이올린·누적분포·오차막대·캔들·네트워크·코드·등고선 등입니다. 카테고리와 검색으로 찾고, 각 차트를 눌러 확대·활용 목적·필요 데이터·주의사항을 확인하거나 후보로 저장할 수 있습니다. 갤러리 샘플은 업무 테이블과 필터를 공유하지 않습니다.

상단 탭과 본문은 동일한 배경·선택색·카드·글꼴·간격을 사용합니다. 업무 화면은 큰 제목과 KPI 카드 없이 **한 줄 필터 → 목적에 맞는 그래프 → 전체 상세표**로 구성합니다. 통합현황은 실적 비중 트리맵·7개 단계의 상태 건수·계획/실적 차이 워터폴, 입고는 제품군별 계획·실적·월별 전체/MYD 가중 진척·월별 물량 추이, 공출은 최신 기준일의 계획·실적 및 MCS/MOD 재공·일자별 누적 추이, 공급은 10월 입고 차이 워터폴·품목별 10월/11월 CHIP 확보율·B/E 재공 구성, 자재는 목표 미달 물량·GEO/상태 교차표·BOH/RTP/OUT 추이를 기본으로 표시합니다. 각 카드에서는 해당 탭의 세 가지 업무 분석 사이에서만 전환합니다.

분석 기준:

- 공출의 비교·재공 차트는 현재 조회 범위의 **최신 NOW_DATE**만 사용합니다. 모든 날짜를 유지하는 본문 표와 달리 스냅샷을 날짜 간 합산하지 않습니다. 추이 차트는 각 날짜를 독립 시점으로 표시합니다.
- 입고의 월별 진척률은 `Σ ACT_DATE / Σ STD_DAY_PLAN`, MYD는 `Σ MYD_ACT_DATE / Σ STD_MYD_DAY_PLAN`입니다. 원본 비율을 단순 평균하지 않습니다. 분모가 0이면 비율을 표시하지 않습니다.
- 공급의 CHIP 확보율은 품목별 원본 10월·11월 값을 비교합니다. B/E는 일반 재공(MDL+TEST+ASSY+YHS1), HOLD, 반품, 불용을 나눕니다. 단위가 다른 EDS 재공(K)은 합산하지 않습니다.
- 자재 부족은 `Σ max(SS_TARGET − M0_BOH, 0)`으로 계산합니다. 다른 품목의 초과 보유로 부족을 상쇄하지 않습니다. GEO/상태 교차표는 금액이나 비율이 아닌 자재 수입니다.
- 통합현황의 단계별 상태는 원본 샘플의 상태 건수입니다. 동일 품목이 여러 단계에 포함될 수 있으므로 고유 품목 수로 해석하지 않습니다. 워터폴의 제품군별 편차 합계는 실적−계획과 일치합니다.

상단에서 검색·분류·기간·상태를 선택하고 차트의 제품군·상태·시점을 클릭하면 AND 조건으로 원본 행에 적용됩니다. 각 차트는 자신의 선택 조건을 제외한 비교 대상을 유지합니다. 초기화는 모든 조건과 정렬을 해제합니다. 탭에 진입하면 전체 원본 데이터로 시작합니다.

표 헤더 클릭은 **오름차순 → 내림차순 → 원본 순서**로 순환합니다. 숫자 열은 숫자 크기로 정렬합니다. 상단 **열 필터**에서는 모든 원본 열에 대해 포함·같음·숫자 이상/이하 조건을 추가할 수 있습니다. 여러 열 조건은 AND로 적용되며 CSV도 현재 조회된 전체 행과 정렬 순서를 따릅니다.

기본정보 열의 연속된 동일값은 상위 분류가 같은 범위에서 세로 병합합니다. 정렬·필터 후 다시 병합을 계산합니다. 실적·수량·진척률·상태는 개별 관측을 보존하기 위해 병합하지 않습니다. 셀을 클릭하거나 Enter/Space를 누르면 해당 원본 행의 전체 필드를 보여주는 상세창이 열립니다. 병합 셀은 포함된 원본 행을 선택해 각각 확인할 수 있습니다. Escape나 닫기로 돌아갑니다.

셀 색상은 **빨강=위험, 노랑=주의, 초록=정상**입니다. 원본 상태·GEO RISK에 우선 적용하고, 진척률·확보율 및 계획 대비 실적은 시연 기준 ≥95% 초록 / ≥80% 노랑 / 미만 빨강을 사용합니다. 통합현황의 상태별 건수는 해당 상태 색상을 적용하며 0건은 중립색입니다. 업무별 공식 판단 기준이 제공되면 이 시연 기준을 교체해야 합니다.

## 데이터 해석

모든 회사명·ITEM·수치는 검토용 **샘플 데이터**이며 실제 실적이 아닙니다. 기존 HTML의 데이터를 재사용합니다. 공급진척 상태는 CHIP 10월 확보율 ≥95% 정상, ≥80% 주의, 나머지 위험으로 파생합니다. 통합현황 상태는 7개 진척·수급 중 위험을 우선합니다. 공출진척 합계는 조회된 원본 행의 합계입니다. 반복되는 날짜별 계획을 합한 값이 기간의 고유 계획을 의미하지는 않습니다.

표는 열 그룹 전환, 페이지 분할, 행 생략 없이 현재 조건에 해당하는 전체 행·열을 표시합니다. **PC 1366×768, 1440×900, 1920×1080**에서 페이지 및 표 스크롤 없이 검증했습니다. 공간에 맞춰 표 글자가 작아집니다. 더 많은 실데이터나 작은 화면에서는 가독성과 전체 표 동시 표시 간 조정이 필요합니다.

실제 데이터 연동 및 권한·접근 제어는 아직 구현하지 않았습니다.

## 브라우저 회귀 검증

실행 중인 로컬 서버를 대상으로 Chromium과 Playwright로 검증합니다. 앱 실행 자체에는 이 테스트 의존성이 필요하지 않습니다.

```sh
npm install --prefix /tmp/my-dashboard-test --cache /tmp/my-npm-cache playwright --no-audit --no-fund
NODE_PATH=/tmp/my-dashboard-test/node_modules node tests/dashboard.cjs
```

테스트는 기본적으로 `/usr/bin/chromium`과 `http://127.0.0.1:8000`을 사용합니다. `CHROMIUM_PATH`, `DASHBOARD_URL`로 변경할 수 있습니다. 병합 표를 펼친 원본 셀 값 일치, 3개 PC 해상도의 넘침, 상세창·병합 행 선택, 숫자 정렬, 열별 필터, 차트 교차 필터, 검색·초기화·CSV, 70종 갤러리와 확대창을 검증합니다. 스크린샷·CSV는 시스템 임시 디렉터리에 저장합니다.
