# MY — Executive Operations Dashboard

경영진용 MYD 운영 대시보드. `index.html`을 브라우저에서 열면 실행됩니다. 빌드, 외부 CDN, API 키가 필요하지 않습니다. `index.html` 한 파일에 최신 CSS·JavaScript를 포함했으므로 이 HTML만 내려받아 열어도 같은 화면이 동작합니다.

로컬 HTTP로 실행하려면:

```sh
cd /workspace/MY
python -m http.server 8000 --bind 0.0.0.0
```

수정 소스는 `dashboard.js`, `dashboard.css`입니다. 변경 후 `python scripts/embed-dashboard.py`로 단일 HTML에 반영하세요. GitHub 원격에 변경을 반영하기 전에는 GitHub의 HTML이 로컬 작업본과 다릅니다.

## 화면과 분석 흐름

- **통합현황**: 기존 샘플 12행 × 36열 전체 표시.
- **입고 실적·진척**: 12행 × 22열, 월별 입고와 계획·실적 비교.
- **공출 실적·재공**: 21행 × 23열, 모든 기준일의 원본 행 표시.
- **공급·CHIP 진척**: 12행 × 30열, 입고 및 CHIP 확보 현황.
- **자재 확보·리스크**: 16행 × 18열, 목표와 M0 보유량, GEO RISK.
- **차트라이브러리**: 데이터셋을 선택하고 비교 막대·도넛·분포·산점도·히트맵·차이 차트로 같은 원본 행을 분석. 기존 50종 참고 차트도 별도로 열 수 있습니다. 참고 차트는 시각화 설명용으로, 데이터 필터와 연결되지 않습니다.

제품군 막대 → 상태 도넛의 구간/범례 → 월·기준일·품목 막대를 클릭하면 조건이 AND로 적용됩니다. 표, 지표, 다른 차트도 함께 바뀝니다. 같은 항목 재클릭, 조건 칩의 ×, 전체 해제로 조건을 해제합니다. 검색과 CSV 내보내기도 현재 필터를 따릅니다. 키보드 Tab으로 차트 항목에 이동해 Enter 또는 Space로 선택할 수 있습니다.

각 차트는 **자신의 선택 조건만 제외**한 데이터를 보여줘 다른 항목으로 전환할 수 있습니다. 지표와 표는 모든 조건을 적용합니다. 탭에 진입할 때마다 전체 원본 데이터로 시작합니다. 서로 다른 품목 코드의 데이터셋을 임의로 조인하지 않습니다.

모든 탭은 통합현황과 같은 **제목 → 상단 필터 → 지표 6개 → 그래프 → 전체 상세표** 구조를 사용합니다. 상단에서 검색·제품군/자재군·응용/패키지/FAM1·월/기준일·상태를 선택할 수 있습니다. 각 차트 카드의 유형 선택으로 비교 막대, 도넛, 수직 막대, 산점도, 히트맵, 부족·초과 발산 막대로 전환할 수 있습니다. 입고 기본 차트에는 전체/MYD 당일 진척과 월별 추이, 공출에는 MCS/MOD 누적 재공과 기준일별 추이, 공급에는 CHIP 10/11월 확보율, 자재에는 월별 BOH/RTP/OUT 흐름을 표시합니다.

셀 색상은 **빨강=위험, 노랑=주의, 초록=정상**입니다. 원본 상태·GEO RISK에 우선 적용하고, 진척률·확보율 및 계획 대비 실적은 시연 기준 ≥95% 초록 / ≥80% 노랑 / 미만 빨강을 사용합니다. 통합현황의 상태별 건수는 해당 상태 색상을 적용하며 0건은 중립색입니다. 업무별 공식 판단 기준이 제공되면 이 시연 기준을 교체해야 합니다.

## 데이터 해석

모든 회사명·ITEM·수치는 검토용 **샘플 데이터**이며 실제 실적이 아닙니다. 기존 HTML의 데이터를 재사용합니다. 공급진척 상태는 CHIP 10월 확보율 ≥95% 정상, ≥80% 주의, 나머지 위험으로 파생합니다. 통합현황 상태는 7개 진척·수급 중 위험을 우선합니다. 공출진척 합계는 조회된 원본 행의 합계입니다. 반복되는 날짜별 계획을 합한 값이 기간의 고유 계획을 의미하지는 않습니다.

표는 열 그룹 전환, 페이지 분할, 행 생략 없이 현재 조건에 해당하는 전체 행·열을 표시합니다. **PC 1366×768, 1440×900, 1920×1080**에서 페이지 및 표 스크롤 없이 검증했습니다. 공간에 맞춰 표 글자가 작아집니다. 더 많은 실데이터나 작은 화면에서는 가독성과 전체 표 동시 표시 간 조정이 필요합니다.

실제 데이터 연동 및 권한·접근 제어는 아직 구현하지 않았습니다.

## 브라우저 회귀 검증

실행 중인 로컬 서버를 대상으로 Chromium과 Playwright로 검증합니다. 앱 실행 자체에는 이 테스트 의존성이 필요하지 않습니다.

```sh
npm install --prefix /tmp/my-dashboard-test --cache /tmp/my-npm-cache playwright --no-audit --no-fund
NODE_PATH=/tmp/my-dashboard-test/node_modules node tests/dashboard.cjs
```

테스트는 기본적으로 `/usr/bin/chromium`과 `http://127.0.0.1:8000`을 사용합니다. `CHROMIUM_PATH`, `DASHBOARD_URL`로 변경할 수 있습니다. 전체 행·열, 상단 필터, 3개 PC 해상도의 넘침, 그래프 유형 전환, 검색·초기화, 키보드 선택, CSV, 라이브러리를 검증합니다. 스크린샷·CSV는 시스템 임시 디렉터리에 저장합니다.
